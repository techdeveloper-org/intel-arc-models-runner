### DL-061 Shared async bridge (WP-03)
- Status: superseded in part by DL-071 and DL-072 (v9.0); see the summary row.
- Context: blocking load, compile, generate, tokenize, embed, GGUF parse and pull run inside `async def` handlers; a replica probe that needs about 52 ms took 2077 ms while one 1 s load plus 1 s generate ran (P4-01, READ+replica). The streaming bridge calls `call_soon_threadsafe(queue.put_nowait)` from a thread, which never raises `QueueFull`, so the retry branch is dead and the sentinel can be dropped; the replica lost 67 of 300 tokens under a 2 s loop stall (P4-03, READ+replica). A disconnected client leaves the worker generating (P4-04, READ+replica). The bridge is copied three times. The engine's `generate_stream` already starts its own inner thread, blocks on bounded `chunk_queue.put` calls from the callback and the worker `finally`, and reads its cancel flag only inside the callback (`openvino_engine.py:299, 323, 328, 334-347`, READ; the mechanism was confirmed by reviewer G2 and the lines re-read in v8.4). Prefill is not cancellable (READ). Whether concurrent `LLMPipeline.generate` calls are safe is a HYPOTHESIS decided by N-03. The per-token bridge cost was measured at 3.7 us (JSON plus timestamp, replica) against 24.9 ms per GPU token (DERIVED), so the bridge is not a throughput lever.
- Options: (A) one helper, dedicated executors, FIFO admission, an ordered channel and a cancel/join protocol (CC-1..CC-4); (B) a helper that blocks the producer until the loop has accepted each chunk (P1-03 option 2); (C) bare `to_thread` keeping three bridges; (D) one helper with an interim `threading.Lock` per engine until the lease exists.
- Decision: A. Three private named executors (`inference` for grant holders, `load` for compiles, `bulk` for pulls, transpiles, GGUF parsing and hashing, each with its own limit) are used only after an async FIFO grant, so waiting never occupies a thread, and `/health` and `/api/ps` read an in-memory snapshot instead of an executor; one executor thread per stream iterates the generator beside the engine's inner pipeline thread (the two are not folded; collapsing them is WP-16); chunk, `done` and `error` are all delivered through `call_soon_threadsafe` so order is call order, and the consumer drains until `done and buffer empty`; **the caller owns a `cancel` event and the engine a private `stop` event** (stop strings and `max_new_tokens` set `stop`, so a normal finish cannot look like a client cancel and lose the tail), checked in the callback and the wait loop; inner-thread puts time out and re-check the cancel event or the queue has no limit (growth bounded by `max_new_tokens`, `le=32768`); the generator's `finally` sets cancel and **joins the inner thread**, the join bounded by `generate_hang_timeout` (expiry marks the lease wedged, the entry leaves the cache index, queued waiters get 503 `engine_wedged`, and a reaper thread keeps the lease and the bytes until the inner thread dies), and only then does the bridge release lease and grant; every streaming route returns a `LeasedStreamingResponse` (a lease whose stream never started, or whose response failed before the first chunk, is released in the response wrapper's `finally`) and runs a `DisconnectWatcher` for streaming and non-streaming requests, unconditionally, tested over a raw socket against real uvicorn (starlette 1.10.0 listens for `http.disconnect` only below ASGI spec 2.4 and uvicorn 0.54.0 advertises 2.3, so the watcher is version insurance and the only cancel path for non-stream handlers); a `client_stall_timeout` cancels a consumer that stops draining; non-stream generate uses the same cancellable callback path but returns `DecodedResults.texts[0]`; `copy_context().run` carries the request id into both threads; mid-stream failures use the SSE/NDJSON error event of CC-11. The admission-time lease and evict-skip (CC-4) ship in this package because offloading makes eviction mid-generate newly possible. N-02 runs before the package is merged.
- Consequences: one place to test loss, cancel and ordering; a hung engine becomes a wedged entry instead of a dead process; routes shrink; a slow client no longer slows generation and a stalled one is cancelled; concurrent requests to one model wait FIFO, as the single compute engine does anyway; prefill is not interruptible and the tests say so; per-stream worst-case buffer is a computed number in the stage record.
- Reversibility: high in isolation (helper is additive, executors private), but valid only in reverse dependency order once WP-04, 05, 14 and 15 exist (CC-13). No ABI or data format involved.
- Source: register rows P4-01, P4-03, P4-04, P4-12; CC-1..CC-4.

### DL-062 Manager concurrency model (WP-03, WP-04, WP-05)
- Status: superseded in part by DL-071 and DL-073 (v9.0): only the sync API, the canonical key and warmup-off-by-default survive.
- Context: `ModelManager._lock` is held across path resolution, eviction, `unload()` and compile, and shared with `record_generation_metrics`, `get_telemetry` and listing (`model_manager.py:133-167`; P4-02, P1-02, P5-03, READ). First-request cost after load is PROVEN (P3-03: CPU TTFT 9.0-14.2 s vs 0.07-0.36 s steady; GPU 134-221 ms vs 20-74 ms); compile duration itself is a HYPOTHESIS (P4-02 "O(10-100 s)", unmeasured). The engine returns one shared object to all callers with one mutable `_telemetry` (P4-05, P1-11, READ); eviction sets `_pipeline=None` under an in-flight request (P4-05, P5-02, READ); every caller of `get_or_load_*` is unleased (`routes_openai.py:167`, `routes_ollama.py:286, 385`, `routes_embeddings.py:52, 92, 146`, `routes_ui.py:389`, `audio_worker.py:211`, `runner.py:117`, `cli/main.py:163`; READ); the cache key uses the raw string and includes gamma and eviction precedes a load that may fail (P4-06, P1-06, READ). Two simultaneous compiles double peak memory on a 6976 MiB shared ceiling (probe PROVEN, effect HYPOTHESIS).
- Options: (A) keep one lock, move scans and unload outside it; (B) CC-3..CC-7 (admission-time lease released by the finishing thread, single flight with shielded waiters, sorted compile slots and failure TTL, hard capacity limit with FIFO capacity queue and timeout, lock hierarchy with `_state_lock` a leaf); (C) one asyncio manager task owning all lifecycle through a queue (cleanest, rewrites the synchronous API the CLI uses).
- Decision: B, with the sync API kept and an async variant added. Acquire is **two-phase**: path resolution and the canonical key outside any lock, then one leaf-lock section that takes the lease (a hit) or publishes a `PendingEntry` carrying the waiters' leases (a miss), so a finished load cannot be evicted before its waiters use it and no I/O happens under `_state_lock`. A lease and its grant have one owner at a time (request, worker or released; compare-and-set, idempotent release): the worker releases in its `finally`, a done-callback releases a job cancelled before it started, and the request code releases when `submit` fails or the stream never starts. A request never holds a lease while acquiring another, and a request needing several engines uses all-or-nothing `acquire_many`. The load runs detached on the `load` executor and waiters await a shielded future, so one cancelled client never cancels the compile; compile slots are taken in sorted device order and a failed load is remembered for a short policy TTL **only when it is deterministic**. The resident count never exceeds `max_loaded_models`; fairness is by global ticket, and a pending load that has waited half of `capacity_wait_timeout` forces its victim into draining (a hot model cannot starve a loader); waiting is by futures in a wait list resolved outside the lock, with `CapacityTimeoutError` (503 + `Retry-After`) on expiry, and until WP-04 `acquire` raises it at once when no idle victim exists. `unload()`, `gc.collect()` and native `close()` run outside `_state_lock` and only at `leases == 0`; finalizers take no lock and append to a lock-free credit queue; each LLM engine has a separate tokenizer instance behind a leaf lock (a HYPOTHESIS until N-03); shutdown cancels active leases, joins with the hang timeout, unloads, then shuts the executors down without waiting. - Status: superseded in part by DL-076 (v9.0): the gate is the design for DF-03; the config-validity fix is built in WP-01 item 01f.
- Context: committed same-model data (qwen-2.5-1.5b on both devices, medium tier medians 41.42 tps GPU and 14.67 tps NPU) gives a per-step time ratio **c = t_draft_step / t_target_step = (1000/14.67) / (1000/41.42) = 68.2 ms / 24.1 ms = 2.82** (P1-07, DERIVED). c is a ratio of times, not of tokens per second, and 2.82 is for the same 1.5B model on both devices, so it is not evidence about a smaller draft (UNMEASURED) and must not be used against NPU drafting in general. Model (a model, not a measurement): per round the draft takes g steps and the target verifies g+1 tokens in v >= 1 target steps, giving S = (1 - a^(g+1)) / ((1 - a)(g*c + v)) for acceptance a; (g+1)/(g*c+1) is its **upper bound at a = 1 and v = 1** (at c = 2.82, g = 4: 5/12.28 = 0.41), and S > 1 there iff c < 1. c < 1 is **necessary for any a** (the geometric sum is at most g+1) but **not sufficient**, because a < 1 and v > 1 only lower S.
